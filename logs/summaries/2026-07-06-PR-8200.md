## Fix strategy — `ancestry-merge` with `-s ours`

`git merge -s ours f59942c453` on `opening-template-on-type`.

- **Before:** build merges #7916 then #8200. LCA(build, #8200) = `v0.8.0`; both sides changed
  the same `ui.py` rows relative to that base → conflict.
- **After:** the `-s ours` merge makes `f59942c453` an **ancestor** of #8200 while keeping
  #8200's tree byte-for-byte (the merge introduces no content). The build's LCA with #8200
  shifts from `v0.8.0` to `f59942c453`; relative to it, #8200's only `ui.py` delta is the
  `RepresentationIdentifier` column + header (the operator change is now shared in the base),
  and nothing else in the build touches that region → clean auto-merge.

This is the "TARGET_PR's files already reflect the conflicting commit's intent (branch was in
the build under different hashes due to a rebase)" case for `-s ours`.
