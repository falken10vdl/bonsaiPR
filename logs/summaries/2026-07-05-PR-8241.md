**Root cause:** #7940 and #8241 are *sibling branches*. Both grew from the same
`Unhide_with_alt_click` commits (shared prefix up to `f0d8a6f4f4`, PR
[#7781](https://github.com/IfcOpenShell/IfcOpenShell/pull/7781)). Above that prefix:

  `select_similar`, `select_ifc_class`, `select_similar_container`, `select_aggregate`,
  `select_by_material`.
- #8241 adds SHIFT+Click remove-from-selection and CTRL+Click filter-selection to the
  same operators, rewriting the same function bodies.

In ascending order #7940 (lower number) merges into the build first; when the build then
attempts #8241, git's 3-way merge sees both sides changing the same regions relative to
their common ancestor (the shared Unhide prefix) → conflict.

## Fix strategy: ancestry-merge (Option A, plain merge with manual reconciliation)

`git merge 7e3a9e4a75` on `Additional_Selection_and_Deselection_Tools`.

Mechanics: making #7940's tip an ancestor of #8241 shifts the merge-base between the
build tip (which contains #7940) and #8241 from the shared Unhide prefix up to
`7e3a9e4a75` itself. From that LCA, only #8241 changes the disputed regions, so the
build's merge of #8241 auto-resolves.

- Not `-s ours`: #7940's content (clipboard concatenation, multi-derive) was genuinely
  absent from #8241 and needed to be incorporated.
- Not rebase: #8241's history was already pushed; the merge adds a single commit
  (fast-forward push, no rewrite) and keeps the PR focused — beyond the shared prefix
  the merge brings only #7940's 5 small commits in 4 files.

## Conflict resolution details

The merge conflicted in the 4 files; each was reconciled to combine **both** intents
(#7940's dedup/concatenate/multi-derive + #8241's remove/filter modes):

- **`aggregate/operator.py` (`select_aggregate`)** — kept #8241's
  `keep_current_selection` seed handling (active object only in remove/filter mode; seeds
  not deselected in those modes) and #7940's `aggregates = {}` dedup dict feeding
  `all_parts = list(aggregates.values())`.
- **`material/operator.py` (`SelectByMaterial`)** — kept #7940's full rewrite
  (selection-derived materials with the clicked material as layer-index hint, fallback to
  the explicit prop, concatenated clipboard) and threaded #8241's
  `remove_from_selection` / `filter_selection` into each `core.select_by_material` call.
  In remove/filter mode the derivation loop uses the active object only — this also
  guarantees a single criteria material, so sequential per-material `filter` calls cannot
  wrongly intersect.
- **`search/operator.py` (`SelectIfcClass`)** — kept #8241's filter branch (early return)
  and remove path (`tool.Blender.deselect_object`), and #7940's clipboard restructure
  (`result = " + ".join(classes)` after the loop; the old incremental `result` variable
  removed). `SelectSimilar`'s `_generate_clipboard_query(reference_values, key)` list
  signature from #7940 auto-merged without conflict.
- **`spatial/operator.py` (`SelectSimilarContainer`)** — kept #7940's multi-container
  derivation and `location = "..."` clipboard concatenation, threaded
  `remove` / `filter_selection` into the per-container `tool.Spatial.select_products`
  call, and restricted derivation to the active object in remove/filter mode (single
  container ⇒ no sequential-filter intersection problem). The operator keeps #7940's
  direct `select_products` loop rather than `core.select_similar_container`.
