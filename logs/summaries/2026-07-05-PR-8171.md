## The conflict

Both PRs add new property templates to the same IFC pset file
`src/bonsai/bonsai/bim/data/pset/EPset_Drawing.ifc`, and both started numbering from the
**same entity ID `#29`**:

- #8238 added `#29 PerspectiveShiftX` and `#30 PerspectiveShiftY` (`IfcReal`).
- #8171 added `#29 RenderOverrides` (`IfcText`).

This is a classic IFC pset ID collision: two independent additions claim the same `#29`,
and both also append their new ID to the `IFCPROPERTYSETTEMPLATE` `HasPropertyTemplates`
back-reference list.

At build time (2026-07-05) #8238 was still an open PR, so the build reported #8171 as
"Skipped — Conflict with other PRs. Merges cleanly with base." Between that build and this
resolution, **#8238 merged into `v0.8.0`** (`da4b2f6eee`), so #8171 now also conflicts with
**base** — the same collision, just relocated into the base branch.

## Why rebase (not ancestry-merge)

Because the conflicting content is now *in* `v0.8.0`, incorporating current `v0.8.0`
resolves both the historical inter-PR conflict and the current base drift in one move. #8171
is a small, self-owned two-commit branch that has been maintained as clean linear history,
so it was rebased onto the current `v0.8.0` tip (`1614791775`) rather than carrying a merge
commit. From the build's perspective the effect is identical: after the rebase the
merge-base between the build (which starts at the `v0.8.0` tip) and #8171 already contains
`#29`/`#30`, so git's 3-way merge sees only #8171's `#31` addition — no contest.

## Files changed in the resolution

### `data/pset/EPset_Drawing.ifc` — ID renumber
Kept #8238's IDs unchanged (higher priority: already merged to base) and renumbered #8171's
entity:
- `RenderOverrides` template `#29` → **`#31`** (GUID unchanged).
- `IFCPROPERTYSETTEMPLATE` `HasPropertyTemplates`: kept `v0.8.0`'s list (which references
  `#29`,`#30`) and appended `#31`.

Validated with ifcopenshell: 30 referenced templates; `PerspectiveShiftX`,
`PerspectiveShiftY`, and `RenderOverrides` all present; `RenderOverrides` = id 31, type
`IfcText`. No runtime code change needed — the `status_render` module references the pset
property by **name** (`RenderOverrides`), not by entity ID.

### `bim/module/drawing/ui.py` — semantic follow-up
#8171's second commit wraps the "Active Drawing" controls in a collapsible
`layout.panel("drawing_settings")` (`body`). #8238 independently added camera-shift rows to
the same `BIM_PT_camera.draw`. The rebase applied both textually cleanly, but #8238's rows
referenced `self.layout` (panel root) while the collapsible commit routes everything through
`body` — so they would have rendered *outside* the collapsible. Fixed the two camera-shift
rows to use `body`, matching the collapsible commit's intent. Amended into the collapsible
commit so the branch stays two clean commits.
